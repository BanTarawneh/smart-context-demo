Build a clickable, front-end-only demo web app for a B2B AI product called
"Smart Context". It will be SCREEN-RECORDED for a product video, so visual
polish and smooth, predictable animation matter more than anything else.
There is no backend, no login, no database, no real API calls — every piece of
data is hard-coded mock data listed below.

=====================================================================
1. TECH + RECORDING REQUIREMENTS
=====================================================================
- React + TypeScript + Vite. Tailwind CSS. Framer Motion for all animation.
- Design for a fixed 1920×1080 viewport (the browser will be full-screen
  while recording). The whole app must fit in one screen with NO scrollbars
  anywhere — no page scroll, no inner scroll. Hide scrollbars globally.
- No dev banners, no toasts from the framework, no cookie bars, no console
  errors. Nothing on screen that isn't part of the product.
- All animations deterministic: same input → same result every time, so a
  scene can be re-recorded identically.
- Font: "Tajawal" from Google Fonts, weights 400/500/700/800/900, used everywhere.

=====================================================================

  applied as text fill.

Style
  - Clean enterprise SaaS. White cards, 12px radius, 1px #E3EAF3 border,
    soft shadow 0 10px 30px rgba(11,20,55,0.08).
  - Every "app" is shown as a desktop window (14px radius, big soft shadow)
    sitting on the #DCE3EC desk colour, inset ~80px from the screen edges.
  - Match the attached "Coordination Agent Mail" screenshot closely: its
    three-column layout, its label style (small uppercase grey labels), its
    field style (label above a light grey input box), its green "complete"
    status chips, and its orange "Fill Into SAP" button.
  - Put the attached logo mark top-left in every Smart Context window, with
    the words "Smart Context" beside it.
  - Checkmarks are small green filled circles with a white tick. They should
    "pop" in (scale 0.5 → 1).
  - Motion: everything eases (ease-out cubic), 250–450ms. No bounce, no spin,
    no 3D. Values that "arrive" fade + slide up 16px. Fields being filled by
    the AI flash a pale cyan background that fades out.

=====================================================================
3. HOW THE DEMO IS DRIVEN
=====================================================================
The app is a sequence of 13 SCENES. Each scene has numbered STEPS.

Keyboard controls (show NO on-screen hint of these):
  →  or Space   next step (moves to the next scene after the last step)
  ←             previous step
  1–9, 0, -, = jump straight to scenes 1–12; Shift+3 jumps to scene 13
  R             reset the current scene to step 0
  A             AUTOPLAY: run the whole demo on the timeline in section 6

A small hidden debug overlay, toggled with the D key, shows
"scene X · step Y · t=12.4s". It must be OFF by default.

Include a fake animated mouse pointer (dark navy arrow with white outline)
that glides to whatever is being clicked in each step and shows a small cyan
ripple when it "clicks". This way I never have to move my real mouse while
recording. Hide the real cursor (cursor: none) across the whole app.

Transitions between scenes: 250ms cross-fade. Within one app (e.g. the
Outlook scenes) use NO fade — just animate the changes so the window never
blinks.
